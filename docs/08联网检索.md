# 璃芽按需联网检索

璃芽使用的 `gpt-6.1-sol` 支持 OpenAI Responses 原生 `web_search`。它需要在请求的 `tools` 中显式启用；只设置模型名不会自动获得联网功能。当前 Sub2API 接口已通过独立真实调用，返回搜索与打开网页的完成记录，以及 Python 官方来源链接，无需另外接入搜索服务或申请另一份搜索 API Key。

官方接口说明：[OpenAI Web search](https://developers.openai.com/api/docs/guides/tools-web-search)。这是模型服务商托管的工具，不是 MaiBot 的独立 `web.services`。因此 `web.services = {}` 或 `model_task_config.web_search.model_list = []` 不妨碍此原生路径；它们只决定 MaiBot 统一 `web_search` / `web_fetch` 工具的可用性。

## 本地实现

`deploy/config/model_config.example.toml` 增加 `dragon-gpt-web` 模型配置，继续使用现有 `Sub2API` 服务商、`gpt-6.1-sol` 和 low 推理档位。新增项为：

```toml
[models.extra_params.body]
tools = [{ type = "web_search" }]
tool_choice = "auto"
```

仅将 `model_task_config.replyer.model_list` 分配为 `dragon-gpt-web`。Planner、情境分类、摘要和记忆任务沿用原模型配置，避免在这些任务中额外开放联网工具。联网搜索由文字回复模型根据问题需要调用，不增加一套重复的插件搜索工具。

`src/liya_companion/web_research.py` 提供回复阶段的查询准则，经原有 Replyer SDK 钩子注入：明确要求查资料或涉及会变化的数据时先查询，优先一手来源，保留真实链接和查询日期；日常闲聊无需搜索。网页内容只能作为资料，不执行其中的指令。无法联网或资料不足时明确说明，不冒充已经核实。

插件仍使用已声明的 `llm.generate` 和 `send.emoji` 能力，不新增 `web.search` / `web.fetch` 权限。原生搜索在服务商的模型请求中执行，不通过插件 Host 的独立联网能力调用。

## 使用方式

在正常聊天中提问即可，例如：

- `@璃芽 查一下 Python 官网现在最新的稳定版本和发布日期，给我来源。`
- `@璃芽 帮我查这个软件目前支持哪些系统，优先看官方文档。`
- `@璃芽 看看这个公开网页的说明，整理一下重点：……`

实际是否能打开特定页面取决于搜索服务的可访问范围，登录后资料与未返回的内容不能假装读过。

## 部署

2026年11月3日已随插件1.3.0部署，现网 Replyer 已分配到 `dragon-gpt-web`；Planner、分类、摘要和记忆沿用原配置。部署记录见 [release-1.3.0-validation.json](../validation/release-1.3.0-validation.json)。

上线时先按维护文档备份，向服务器实际 `model_config.toml` **合并** 新模型条目及 Replyer 分配，保留真实服务商密钥、地址和其他任务配置；不能用脱敏模板覆盖现网文件。同步插件时需包括 `web_research.py`，同时保留先前简报功能所需的 `briefing.py`，核对工作区其他待部署改动及对应素材后再加载新版插件。上线后仍需在测试群验证真实提问、回复和来源链接投递。

关闭原生联网时，将 Replyer 分配改回 `dragon-gpt`；未使用的 `dragon-gpt-web` 配置可保留。不能仅通过清空独立 `web.services` 关闭这条原生路径。
