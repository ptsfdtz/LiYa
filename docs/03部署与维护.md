# 璃芽部署与维护

现网位于 `10.249.254.57`，SSH 别名为 `marsIntranet`，部署根目录为 `/opt/dragon-maibot`。本地项目目录保存设计和参考文件，运行中的机器人继续使用服务器上的配置与数据。

## 日常操作

在本机终端登录后执行维护命令。

```powershell
ssh marsIntranet
```

```bash
cd /opt/dragon-maibot
docker compose ps
docker compose logs --tail 100 core
docker compose restart core
python3 /opt/dragon-maibot/backup.py
```

原始日志可能包含用户消息和凭证相关内容，排查时只提取必要行。无需为本地文档整理重启服务器。

WebUI 通过 SSH 转发访问，保持转发终端运行。

```powershell
ssh -N -L 127.0.0.1:18001:127.0.0.1:18001 marsIntranet
```

浏览器打开 `http://127.0.0.1:18001/`。登录令牌位于服务器 `data/webui.json`，应在服务启动完成后读取当前值；不要缓存重启前令牌连续重试，以免触发登录限流。QQ 后台用于名称、头像和群接入管理；MaiBot WebUI 用于模型、人格、插件与记忆管理。

## 新服务器准备

新服务器需要 Docker Engine、Compose、可访问 QQ 和模型服务的网络，以及可用的 QQ 机器人应用。现有 SSH 别名只属于当前电脑配置，新机器需自行配置登录方式。

1. 创建 `/opt/dragon-maibot`，以及 config、data、plugins、logs、patches、embedding-models 和 backups 子目录。
2. 将本目录 `deploy/compose.example.yaml` 复制为部署根目录的 `compose.yaml`，将 `deploy/patches/` 和 `deploy/backup.py` 放到相应位置。
3. 将 `src/liya_companion/` 整个复制到服务器 `plugins/liya_companion/`。插件需要保持该目录名。
4. 安装 [QQ 官方适配器](https://github.com/Mai-with-u/MaiBot-QQ-Adapter)；本次验证版本为0.4.6，目录为 `plugins/qq_official_adapter/`。本地项目不重复打包第三方适配器源码。
5. 将 `deploy/config/bot_config.example.toml`、`model_config.example.toml` 分别复制为 config 下的实际文件。将 `qq_adapter_config.example.toml` 复制为适配器目录的 `config.toml`。
6. 填写自己的 QQ AppID 与 AppSecret，将模型配置中实际服务商的 `api_key` 占位值替换为有效凭证；`LocalMemory` 使用无鉴权的内部地址。对话服务使用 openai_responses，模型为 gpt-6.1-sol，推理档位 low。人格和记忆设置已经保留在模板中。
7. 将 `api.example.json` 复制为根目录 `api.json`，填写实际服务地址、API Key 与模型名。此文件按 Compose 挂载到 `/run/secrets/provider.json`；同时核对 model_config 中的服务商配置，避免两处信息不一致。
8. 检查文件权限，将凭证文件限制为管理员读取。模板中的 `REPLACE_ME` 和 `YOUR_QQ_APP_ID` 必须填写后再启动。

以上模板根据已部署配置脱敏导出，使用前应复核聊天启用范围及管理员相关配置。它们用于重建参考，不是带真实凭证的一键安装包。

```bash
cd /opt/dragon-maibot
docker compose config --quiet
docker compose up -d embeddings
docker compose exec embeddings ollama pull bge-m3
docker compose up -d core
docker compose ps
```

确认 QQ 适配器已连接；原生记忆自检应显示维度1024、runtime_ready、retrieval_ready，且 degraded 为 false。随后检查人格档案并在测试群中明确提及机器人，验证文字和图片收发。当前只验证了现网部署及备份完整性；新机器从零重建仍应按上述步骤验收。

## 备份与恢复

服务器 cron 位于 `/etc/cron.d/dragon-maibot-backup`，每天20:23执行备份，使用服务器 Asia/Shanghai 时区。对应配置保存在 [cron 文件](../deploy/dragon-maibot-backup.cron)。

[backup.py](../deploy/backup.py) 对 data 下实际 SQLite 数据库使用 sqlite backup API 获取一致快照，再逐个执行 integrity_check。归档包含 Compose、config、plugins、api.json、data、backup.py 和 patches；排除实时数据库旁的 WAL、SHM、锁文件。备份文件权限为600，现有验证覆盖4个 SQLite 数据库。

备份不包含 embedding-models、logs、source 和完整 artwork 工作区。恢复时需保留模型缓存或重新拉取 bge-m3；素材制作原稿应另行保管。脚本当前不自动清理旧备份，应定期检查磁盘使用和归档保留情况。

恢复时先解包到独立暂存目录，核对配置、镜像、补丁和数据库完整性。正式替换前停止 core 并保留现有目录及最新备份，避免覆盖运行中的 SQLite。将验证后的内容恢复到 `/opt/dragon-maibot`，恢复凭证权限后启动 embeddings、core，重新验证 QQ、记忆和状态保存。只恢复到其他路径时还需调整 backup.py 中的固定根目录。

## 原生记忆兼容补丁

当前 Compose 用只读挂载替换 `src/A_memorix/core/runtime/services/search_hit_processing_service.py`。原函数只接受字典 metadata，而 SQLite 查询可能返回 JSON 文本，导致部分带聊天范围的 web_import 被当作全局来源。

补丁只在范围解析前将 JSON 文本转换为字典。原文件与修复文件均在 `deploy/patches/`，修复文件 SHA256 为 `575c12bf1d77db91b25df1cfcf1f31abb7fa525bab26a211201a7bbfa93bb705`。升级 MaiBot 前先检查上游同名文件和修复情况，不能把旧版整文件覆盖到未知新版；随后重跑跨聊天隔离验证。
