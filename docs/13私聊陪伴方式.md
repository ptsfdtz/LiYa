# 私聊陪伴方式

当前为1.5.1，服务器源码提交 `ab3c88ebafd053b06ed6d5bdd627952ee0d2548b`，发布目录 `/opt/dragon-maibot/releases/liya-private-20261104-175108`。

私聊发送普通正文，不再显示引用框。原生 `private_quote_frequency` 设为 `never`；QQ适配器另修正私聊的隐式引用回退：`reply_to` 继续作为被动发送凭证，不自动生成 `message_reference`。群聊原有行为保留。适配器补丁按原始及补丁哈希锁定，见 `deploy/host/build_qq_private_patch.py`。

消息等待依据静默窗口、文本信号和Planner的语义判断。普通完整表达默认等待最后一条后7秒；句尾逗号、连接词、未闭合括号等未完信号等待12秒；明确还没说完或等我说完则等待后续消息；明确说完了、发完了、你说吧等缩短为1.5秒。续发重新计时，私聊不受群聊整批8秒或提及4秒上限截断。Planner遇到语义未完继续wait，不用“说完了吗”打断。QQ无法提供尚未发送的输入内容，所以不能保证任意停顿都能百分之百判断准确。

回复生成期间如果本人继续发来私聊消息，旧正文在发送前被拦截，后续基于完整上下文重新回应。群聊仍按原有成员和引用归属处理。普通回应先接住具体情绪和分享，允许温柔、俏皮和安静相处；以陈述句自然结束，不默认追问情绪原因、不每轮制造任务或新问题。确实影响执行请求的必要信息仍可以澄清，不采用删除问号或截断正文的做法。

59项本地测试与49项Host检查通过，包括原有共同经历、个人记忆、提醒和群聊检查，以及新增的私聊连续补充、显式等待、生成中续发取消和QQ被动凭证保留。5个真实模型用例覆盖截图连续两句话、安静陪伴、分享小事、必要澄清和没说完时wait。模型用例只验证所列风格与规划，不替代工具能力验收。

真实桌面QQ最终实测：明确没说完后等待70.58秒未输出正文，补全并表示说完后一次回应，没有引用框或追加反问。最初151A两条消息实际间隔28.35秒且当时适配器引用回退尚未修复，记录为未通过；不将其冒充普通7秒窗口合批验收。普通窗口及生成中续发拦截目前由隔离检查证明。
