# 按需群聊简报

1.3.0 已部署 `liya_group_briefing` 工具，当前补丁版为1.3.1。它在当前 QQ 群内被明确请求后，按实际保存的消息生成约200到400字的小简报，包含主要话题、结论与进展、待办与未决问题。工具返回简报给原生 Planner，由正常回复流程发送；工具自身不主动发消息，也不创建定时任务。

## 使用示例

| 群内请求 | 查询范围 |
| --- | --- |
| @璃芽 整理今天的群聊 | 北京时间当天00:00至当前时刻 |
| @璃芽 整理昨天的讨论 | 北京时间昨天00:00至今天00:00 |
| @璃芽 总结前100条消息 | 最近100条已保存的消息，排除当前请求 |
| @璃芽 总结最近两小时的聊天 | 当前时刻向前两小时 |
| @璃芽 整理11月2日18点到11月3日12点的群聊 | 指定日期时段；年份结合当前日期确定，不明确时应澄清 |

工具参数为 `mode`（today、yesterday、latest、recent、range）、`count`（默认100）、`hours`（默认24）、`start` 和 `end`。起止时间使用 `YYYY-MM-DD HH:MM`，没有偏移时按北京时间解释；起点包含、终点不含。未指定范围时使用今天。`stream_id` 和 `group_id` 来自 Host 当前聊天执行上下文，不作为模型可选参数公布；原生组件限制为 QQ 群聊，私聊请求会拒绝。

## 记录覆盖

使用现有 `incoming` 记录，按机器人接收并存储的时间筛选，只读取当前聊天流，不调用跨聊天长期记忆。记录保留30天；单次最多2000条、约60000字符源材料，超过上限明确要求缩小范围。消息较多时逐段整理后合并，不静默丢弃中间记录。模型失败、超时或没有记录时均返回失败提示。

新消息同时保存当时的昵称，文本最多4000字；超长消息会被标记。旧数据库通过增加字段升级，原消息和关系保留，旧版达到800字上限的消息会标为可能截断。旧记录未保存当时昵称时不推断身份。心情分类仍只使用前800字。

每份简报包含时间范围、采用的消息条数及覆盖说明。记录不足100条时会明确说明实际条数。图片、语音、文件仅能使用已有文字处理结果，不假装解析未读取的附件。

适配器0.4.6源码支持 `GROUP_MESSAGE_CREATE` 和 `GROUP_AT_MESSAGE_CREATE`。是否能整理未 @机器人的讨论，取决于 QQ 是否实际向机器人推送了普通群消息；代码支持并不等于 QQ 侧已经开通。接入前或漏收期间的消息无法凭空补齐。

### 只查到总结请求时

2026年11月3日的新群实际排查发现：只保存了1条 @璃芽的总结请求，截图中两条普通发言没有进入记录；排除请求本身后可总结消息为0。日志确认简报工具已执行。1.3.1 在这种空记录情况下会返回明确的接收设置说明，不再只提示“没查到，请把记录发来”。

群主可在手机QQ打开该群，点璃芽头像进入设置，查找“机器人可获取的群聊消息范围”，选择“获取群内全部消息”。[接入项目的手机操作说明](https://github.com/zaofan-make/dsh-qqbot/blob/main/docs/USER-GUIDE.md)。不同客户端入口可能不同；不能仅凭“没有普通消息”断言用户当前选中了哪一档。

改完后先发两条不 @机器人的普通消息，再发“@璃芽 总结最近10条”。需要同时核对普通消息入库和工具结果，不能仅以机器人能回复 @消息作为接收范围验收。开启前没有推送的历史消息不会自动补齐。

用户随后在手机端重新配置并发送测试消息，后台于23:32收到两条普通测试消息。23:33的真实“最近10条”请求成功调用简报工具，读取3条可用记录并生成正文，原生 Replyer 与 QQ 发送流程确认已发送。因此本次已实际验证普通消息接收、入库、按范围查询、模型整理和群内发送；记录见 [release-1.3.1-validation.json](../validation/release-1.3.1-validation.json)。

## 验证与上线

独立单元测试不依赖 SDK、QQ 或模型服务：

```powershell
python -m unittest discover -s src/liya_companion -p test_*.py -v
```

`tests/test_briefing_hooks.py` 需要实际 MaiBot SDK 和 Host；使用临时 SQLite 与模拟模型检查工具注册、群聊范围、超时声明、请求排除、重试缓存、开关和失败返回，不发送群消息。原有 `tests/test_hooks.py` 继续检查聊天和表情契约。

2026年11月3日，使用现网容器安装的 MaiBot 1.3.19 与 SDK，在 `/tmp` 独立目录运行本地源码及当前素材：21项状态与简报单元测试、4项简报 SDK 契约检查、10项聊天与表情契约检查全部通过。所有数据、模型和发送器均为测试对象；未执行真实模型质量、自然语言工具选择或 QQ 投递验收。结构化证据见 [briefing-validation.json](../validation/briefing-validation.json)。

本次已备份并部署1.3.0，运行时工具注册和原状态保留检查通过。部署后以临时数据库和真实模型生成了两条模拟讨论的简报，覆盖条数及说明正常；未向 QQ 群发送测试消息。真实群内自然语言工具选择、日期解析和普通群消息接收覆盖仍应结合实际使用验证。插件配置 `briefing_enabled` 默认开启，可在 WebUI 关闭。
