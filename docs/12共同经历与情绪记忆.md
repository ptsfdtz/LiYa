# 璃芽共同经历与情绪记忆

目标：让璃芽在相关话题出现时，召回当前聊天中同一成员明确说过的重要经历，并用这些证据和近期对话理解情绪。保留重启后的连续性，允许查询、更正和删除，不把发言记录当作已经核实的现实事实。

本次实现版本为1.5.0。情绪仍是角色状态模拟，不能据此证明具有主观感受。

2026年11月4日17:37已上线，提交`ddd3831`，发布目录`/opt/dragon-maibot/releases/liya-memory-20261104-173656`。插件、QQ连接、原生记忆就绪、源码和素材哈希、数据库完整性检查通过；原有数据计数保持，经历表和情绪来源字段已建立。发布证据见[release-1.5.0-validation.json](../validation/release-1.5.0-validation.json)。

## 工作流程

1. 收到实际消息后，保存真实聊天、成员和消息来源。
2. 从同一成员的近期消息及共同经历中召回相关记录，提供给情境分类器。
3. 分类器返回事件、强度、是否值得保存及实际使用的记忆ID。程序校验记忆ID来自本次召回，模糊续接候选不作为确定关联的情绪证据。
4. 只有本人重要进展、困难、成果等被分类为值得保存，且通过来源检查，才保存历史原话。普通群友互聊、引用、图片、删除与更正请求不自动存成经历。
5. Planner和Replyer在生成前都收到当前成员的相关经历。模型故障时沿用已有心情，不伪造记忆写入成功。

新记忆位于原有 `conversation.sqlite3` 的 `experiences` 和 `experience_terms` 表，不新增数据库或第三方依赖。记录包含聊天、真实用户、原始消息ID、时间、原话、当时事件和截断标记。原话最多800字，并明确标记截断。它们是历史发言证据，不是永久人物标签。

中文双字词和英文词建立倒排索引，按当前话题匹配，从最多200个候选中取3条；排序以词语重合为主、近期程度为辅。没有词语重合时，只有“过了、那件事、上次”等续接表达才可能召回最近30天内的候选，明确标记不确定。多个候选不强行认定同一件事。此版本不保证同义改写和复杂隐喻的语义召回；原生A_Memorix仍负责原有事实与向量记忆。

经历不会随原始短期聊天30天清理自动消失；相关的旧经历仍可经索引找到。查询工具一次最多列出100条当前成员经历。不回填升级前的历史，避免把旧引用、多人转述或已删除信息重新导入。

## 心情连续性

原有平滑更新、1.5小时半衰期和3小时后恢复平静继续适用。普通neutral接话只标记消息已处理，不清空上一轮感受，也不重新计算衰减起点。`mood_source`保存引发当前感受的消息ID，`evidence`保存经校验的相关经历ID，供追溯使用；不向群成员播报数值。

## 查询、更正与删除

沿用 `liya_personal`：`list`返回原生事实、相处偏好、话题及`experiences`；以`ep_`开头的ID表示共同经历，可作为`correct`或`forget`的target。更正内容必须出现在本人当前请求原话中。未知条目、其他成员条目和缺少明确意图的操作会失败。

删除会清空经历原话及其检索词，保留不含正文的来源墓碑，阻止重试重新导入。更正会使旧条目失效，并用当前明确原话建立新条目。由旧来源生成的话题摘要会关闭并清空，插件注入的近期记录与引用会遮蔽旧来源；由该经历支撑的心情也会重置。

这些操作管理本插件的共同经历。原始QQ消息、MaiBot原生聊天、公共摘要、原生个人事实和历史备份有各自的管理范围，不能把本次成功回执解释成全部数据都已删除。若同一内容曾单独存为原生个人事实，需要分别删除该事实。

设置 `plugin.experience_memory_enabled=false` 可关闭新经历的自动保存及召回，已有经历仍能通过工具查询与管理。群聊、私聊和不同成员保持原有隔离。

## 验收与发布

- 本地：`python -m unittest discover -s src/liya_companion -p test_*.py -q`，59项通过。
- 现网镜像隔离检查：`python scripts/check_chat_runtime.py --approved-assets`，42项通过。使用临时数据库和模拟发送器，不向QQ发送。
- 真实模型：`scripts/evaluate_experience_models.py`在隔离目录运行。4项通过：重要经历保存、插件重载后召回并更新情绪、根据真实来源生成回应、虚构故事不写入。
- 模型证据：[experience-model-results.json](../validation/experience-model-results.json)。真实分类调用抽样约3.9至5.85秒；现有6秒超时仍适用，超时当轮不会新建经历，不阻断正常回复。

发布使用 `scripts/release_experience_memory.py prepare`，通过源码和Git状态检查后，再执行`activate`。它仅替换本次6份插件文件，备份原有配置和数据，保存旧文件及激活记录；保持素材、Host补丁、凭证和现网配置。数据库采用增加字段与表的兼容升级。验收使用原有只读`verify_chat_release.py --stage <新发布目录>`，结果写入`validation/release-1.5.0-validation.json`。

真实QQ群端到端验收由成员发起：先说一件具体待办，之后带明确主题报告进展；也可查询记忆并要求删除指定经历。隔离测试和运行状态检查不等于QQ端到端验收，不自动向群里投递测试消息。
